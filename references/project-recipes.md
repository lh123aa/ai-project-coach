# 高频小项目路径库

选题卡住、或用户说"随便什么都行"时查这里。每个项目都按"两小时出成品"设计。
**只取一个用，不要把整份清单丢给用户。**

## 1. 一条能直接发的文案（朋友圈 / 小红书）

- **成品**：一条 150 字内的文案 + 一张配图
- **三步**：① 定"发给谁、想让他做什么" → ② 出两版让他二选一 → ③ 定稿并生成配图
- **第一步问**：这条是发给谁看的，你想让他看完做什么？
- **卡点**：文案空泛 → 让他补一个具体细节（时间、数字、地点、原话）

## 2. 一周工作周报

- **成品**：一页周报，含本周完成、问题、下周计划
- **三步**：① 让他口述这周干了啥（越乱越好）→ ② 你整理成条目让他删改 → ③ 定稿成可直接交的格式
- **第一步问**：这周你手上大概做了哪几件事？想到哪说到哪就行
- **卡点**：他说"没啥可写" → 问"哪件事最费时间"，从那件写起

## 3. 一堆杂数据整理成表格

- **成品**：一份字段统一、能直接用的表格
- **三步**：① 把原始内容粘进来 → ② 定字段和排序规则 → ③ 出表并检查异常值
- **第一步问**：你手里这份东西是从哪来的、最后想按什么分类看？
- **卡点**：数据脏 → 先只清一列做示范，再让他指出下一列的问题

## 4. 一份 8 页分享 PPT

- **成品**：8 页可放映的 PPT（封面 + 目录 + 5 页内容 + 结尾）
- **三步**：① 定主题和听众 → ② 出大纲让他砍 → ③ 生成成品并改一页
- **第一步问**：这次讲给谁听、讲完你希望他们记住哪一句话？
- **卡点**：页面太多 → 强制砍到 8 页，多出的内容挪到备注

## 5. 三天旅行行程表

- **成品**：按天分时段的行程表 + 预算 + 备选方案
- **三步**：① 定城市、天数、同行人 → ② 出两版节奏（紧凑/松弛）让他选 → ③ 补交通、预算、雨天备选
- **第一步问**：去哪儿、几天、跟谁一起？
- **卡点**：景点堆太多 → 每天只留 2 个主点位，其余列为"顺路可选"

## 6. 简历改写 + 一分钟自我介绍

- **成品**：一页简历的重点段落 + 一段能背下来的自我介绍
- **三步**：① 让他贴现有简历或口述经历 → ② 挑一段改成"动作+结果" → ③ 套用到其余段落，并出口头版
- **第一步问**：你要拿这份简历去投什么岗位？
- **卡点**：全是职责没有成绩 → 追问"这件事做完，数字或结果是什么"

## 7. 随手记 / 录音 → 会议纪要

- **成品**：决议、待办、负责人、时间四栏的纪要
- **三步**：① 把原文或录音丢进来 → ② 抽出待办让他补负责人 → ③ 出定稿
- **第一步问**：这份纪要发给谁、他们最关心哪一类信息？
- **卡点**：内容太散 → 只保留"谁在什么时候做什么"的句子

## 8. 一张活动海报

- **成品**：一张竖版海报（含标题、时间地点、二维码位）
- **三步**：① 定活动名和一句话卖点 → ② 出两版风格让他选 → ③ 生成图并改字
- **第一步问**：这个活动一句话怎么介绍、给谁参加？
- **卡点**：字太多 → 主标题不超过 12 字，其余压成三行

## 9. 30 秒短视频脚本

- **成品**：分镜表（画面 / 口播 / 时长）+ 一句钩子
- **三步**：① 定主题和平台 → ② 出两版开头钩子 → ③ 补完整分镜
- **第一步问**：这条视频你想让别人看完记住什么？
- **卡点**：没有钩子 → 前 3 秒必须有一个反常识或具体数字

## 10. 装修 / 搬家 / 婚礼预算表

- **成品**：分类预算表 + 合计 + 超支预警项
- **三步**：① 定总预算和必花项 → ② 出分类表让他填数字 → ③ 标出可压缩项
- **第一步问**：总共打算花多少、哪几项是绝对不能砍的？
- **卡点**：数字不全 → 先用行业区间占位，标黄让他替换

## 11. 读书笔记 / 一个月学习计划

- **成品**：一页笔记或一张四周计划表
- **三步**：① 定目标和可用时间 → ② 拆成每周动作 → ③ 出表格并定检查点
- **第一步问**：你想在多久之后、能做到什么程度？
- **卡点**：计划太满 → 每周只留 3 个动作，其余列为选做

## 12. 一封难写的邮件 / 一段沟通话术

- **成品**：一封可直接发的邮件，或三段式沟通话术
- **三步**：① 说清对象、目的、最坏结果 → ② 出两版语气（硬/软）→ ③ 定稿并给一句"如果对方拒绝怎么回"
- **第一步问**：这封邮件发给谁、你希望他看完做什么？
- **卡点**：情绪太重 → 先写事实段，再加立场段，最后加请求段

## 选品原则

- 优先选**他今天就要用**的，不要选"学了以后有用"的。
- 优先选**产出能截图发人**的，成就感来自被看见。
- 他给的方向太专业（写代码、做数据分析）时，先砍到"能看懂结果"的最小版本，别一上来教工具。
